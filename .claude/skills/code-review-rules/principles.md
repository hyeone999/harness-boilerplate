# 코드 품질 4원칙

출처: https://frontend-fundamentals.com/code-quality/code/

원문 요약만으로는 추상적이라 리뷰에서 걸러지지 않는다. 실제 사례와 함께 적는다. 프로젝트에서 새 사례가 생기면 여기에 덧붙인다.

## 1. 가독성

### 맥락 줄이기

같이 실행되지 않는 코드를 한 함수에 두지 않는다. 구현 상세는 추상화한다.

❌ 상세 화면 한 파일 574줄 — 히어로·상태 토글·탭·정보·미디어 그리드가 한 파일
✅ `DetailHero`, `StatusRow`, `InfoTab`, `MediaTab`으로 분리 (190줄)

스크롤 스냅·마스크 그라디언트 같은 세부는 하위 컴포넌트 안으로 넣어 호출부가 `<ShortcutList items={...} onPress={...} />`만 알게 한다.

### 이름 붙이기

복잡한 조건과 매직 넘버에 이름을 준다.

❌ `items.length >= 3`
✅ `const SCROLLABLE_FROM = 3;` → `items.length >= SCROLLABLE_FROM`

### 위에서 아래로 읽히게 하기

시점 이동을 줄인다. 삼항 연산자를 중첩하지 않는다.

❌ `t === "info" ? "정보" : "미디어"`
✅ `TAB_LABEL[t]` (맵으로 분리)

## 2. 예측 가능성

### 같은 종류의 함수는 반환 타입을 통일한다

같은 계층의 API 함수가 어떤 건 `data`를, 어떤 건 응답 전체를 반환하면 호출부가 매번 확인해야 한다.

### 숨은 로직을 드러낸다

함수 이름에 없는 부수효과를 넣지 않는다.

❌ setState 업데이터 안에서 저장소 쓰기 + 외부 변수 대입
✅ 상태 계산과 저장을 분리

### 이름이 겹치지 않게 한다

같은 이름이 다른 의미로 쓰이면 오해가 생긴다. 한 화면의 `rating`(별점)과 다른 화면의 `rating`(관람등급)처럼 겹치면 이름을 나누거나 최소한 주석으로 구분한다.

## 3. 응집도

### 함께 수정되는 파일을 같은 디렉터리에 둔다

기능 단위로 묶는다. 기술 계층으로 쪼개지 않는다.

✅ `features/contentDetail/{ContentDetailScreen.tsx, components/, hooks/, constants.ts}`

### 매직 넘버를 없앤다

값이 바뀔 때 함께 바뀌어야 할 것들을 상수로 묶는다.

✅ `ITEM_PITCH = LOGO_SIZE + GAP`

## 4. 결합도

### 책임을 하나씩 관리한다

❌ 상태 훅이 상태 관리 + 저장소 직접 호출 + 키 네이밍까지 담당
✅ 저장을 서버로 옮길 때 훅 내부만 교체 — 호출부는 그대로

한 파일이 커지면 책임이 여럿이라는 신호다.

### 중복 코드를 허용한다

성급한 공통화보다 낫다. 단, **같은 목적의 로직이 두 벌로 갈라지면** 합친다.

❌ 이미지 폴백 처리가 두 화면에서 따로 구현 — 한쪽에만 uri 변경 시 리셋 처리가 있었다
✅ 공용 `FallbackImage`로 통합

### Props Drilling을 지운다

3단계 이상 내려가면 컴포지션이나 컨텍스트를 검토한다.
